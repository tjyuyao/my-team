> **v0.7.0 — Manifest-based policy-controlled tool runtime prototype**
> 基于 Manifest 和策略控制的工具运行时**原型**。

**P1 定义（本版本的完成标准，非全量安全/隔离承诺）：**

```text
v0.7.0 P1 = 工具契约（ToolManifest）· 策略检查（OperationPolicy）·
            受限本地工具（apply_patch/run_tests/git_diff/git_status）·
            基本取消语义（逻辑取消 + 结果 fencing）
```

**Tick 协议**：10-phase（Ingest → Freeze → Schedule → Observe →
Decide → Validate(PreValidate) → **Act** → Commit(CommitValidate) →
Publish → Audit）；Act 是显式阶段（注册/stage，绝不应用）；
Commit 是唯一应用者。测试：test_phase_semantics.py
（phase order / validate 无副作用 / act 只 stage / commit 只应用
validated）。

## 1. ToolManifest + OperationPolicy（P1-1，f77846f）

- `ToolManifest`（frozen dataclass）：name/version/schema/capabilities/
  effect_types/execution_class（PURE/READ_ONLY/LOCAL_DETERMINISTIC/
  STAGED_MUTATION/LOCAL_PROCESS/SANDBOXED_PROCESS/
  EXTERNAL_IRREVERSIBLE）/deterministic/idempotent/reversible/
  requires_network/filesystem_scopes/max_runtime_ms/max_output_bytes/
  supports_cancel/requires_approval/retry_policy/
  possible_side_effects（本轮新增，LOCAL_PROCESS 诚实披露）
- 注册即校验（ToolManifestError）；执行类一致性规则
- `OperationPolicy`（默认拒绝）：白名单/审批/网络/文件系统作用域/
  墙钟/输出上限/不可逆
- ToolRegistry policy gate（policy_denied / requires_approval）；策略
  启用时无 manifest 工具一律拒绝

## 2. 多阶段 Validate（P1-2，27835fc + 本轮 be4765e）

原则固化于注释/SPEC/docstring（并有测试断言 test_validate_docstring_
states_principle）：

```text
PreValidate（Phase 6）      — "是否允许尝试？"
Executor Admission（未来）   — "执行器是否可接受？"（v0.8，无 worker 池）
CommitValidate（Phase 8）    — "现在是否仍可提交？"
Apply-time check（Commit 内）— "应用时仍一致？"（本轮新增）
```

- PreValidate：Check 1d manifest+policy、Check 4 task 有效性+deadline；
  全部失败带**结构化 error_code**（本轮新增）：CAPABILITY_DENIED /
  TOOL_MANIFEST_MISSING / POLICY_DENIED / APPROVAL_REQUIRED /
  BUDGET_EXCEEDED / DUPLICATE_REQUEST_ID / TASK_NOT_FOUND /
  DEADLINE_EXCEEDED / INVALID_ARGUMENT（ActionResult.error_code +
  审计 details.error_code；PERMISSION_DENIED 保持为审计类别）
- Act：LLM budget 提交时复查（registry 在飞 + 本 tick 提交数）
- CommitValidate：check_task（TASK_UPDATE 指向存在、未取消、未终态、
  未过 deadline 的 task → 局部 FAILED）
- **Effect 分组原子性**（本轮新增）：StagedEffect.group_id +
  atomicity（per_effect / group）；DelegateIntent = TASK_CREATE +
  EMAIL_SEND 同组——组内任一成员 CommitValidate 失败或冲突落败 →
  全体 FAILED（局部，无整 tick 回滚）
- **局部失败与跨 effect 回滚的边界**（本轮明确）：CommitValidate/
  group/apply-time check 失败 = effect 级局部失败（无回滚，epoch
  不变）；apply 期间抛异常（内核错误如重复 TASK_CREATE）=
  整 tick 回滚（file_previous/KB/email/task 恢复 + epoch bump +
  **scheduler claims requeue**——本轮新增：回滚后激活完成标记失败、
  唤醒事件重新排队，agent 下一 tick 重新激活并观察回滚后的状态）

## 3. Snapshot 读一致性（证据）

机制（simulation.py）：
- **Phase 1 Freeze**（`_build_snapshot`，simulation.py:1547）为每 agent
  捕获不可变 `private_files` 视图（files: relpath→content + dirs，
  二进制跳过），冻结于 tick 边界
- **Observe/Act 的 read/ls 消费该视图**（`context.read_view`，
  handle_read/handle_ls 视图分支优先，simulation.py:373/403；
  Act 经 `snapshot["private_files"]` 注入，simulation.py:1855）
- **PrivateStore 仅在 Commit 期被修改**（_phase_commit 的
  FILE_WRITE/FILE_PATCH 分支；回滚经 file_previous 恢复）

测试证据（tests/test_snapshot_views.py，4 个）：
- `test_same_tick_reads_use_frozen_snapshot` — read 不见同 tick 写入
- `test_next_tick_reads_see_committed_file` — 下一 tick 读到已提交内容
- `test_file_write_rollback_restores_previous_content` /
  `test_file_write_rollback_removes_new_file` — 回滚恢复文件

（v0.6.0 报告已含此测试文件；v0.7.0 报告补上明确引用。）

## 4. 受限工具（P1-3，24ff837 + 本轮 be4765e）

| 工具 | execution_class | 语义 |
|---|---|---|
| apply_patch | STAGED_MUTATION | 严格 unified-diff（格式校验/上下文冲突/新文件/删除/重叠拒绝）；Act 对冻结视图校验；**FILE_PATCH 携带 base_hash/patch_hash/new_content_hash**；**应用时刻**复查当前内容 hash——同 tick 写入使 patch 过期 → 局部 patch_conflict（本轮新增，防过期 patch 覆盖新内容）；file_previous 回滚 |
| run_tests | **LOCAL_PROCESS**（本轮重分类，原 SANDBOXED_PROCESS 撤销） | 诚实声明：超时（进程组终止）+ 输出截断 + 无 shell + 固定 cwd；**无**只读挂载/网络拒绝/资源限制；possible_side_effects = file_write_local/process_spawn/possible_network（执行测试代码 = 执行不可信代码）；requires_network=True |
| git_diff / git_status | READ_ONLY | 只读 git，cwd 固定仓库根，命令系统构造 |

- sandbox_tools.py：list 命令强制（Popen(str) 走 shell，显式拒绝）、
  killpg 无孤儿、输出截断带标记
- SANDBOXED_PROCESS 保留枚举值，但**无内置工具声明**——真正隔离
  达成前不得声明（SPEC §8.7 分类标准 + OI-001）

## 5. 超时与取消（P1-4，18f6964 + 本轮 be4765e）

- 本地进程工具超时 → `tool_timeout` 错误码 + TOOL_TIMEOUT 审计
- `cancel_operation` 返回 **CancellationResult**（本轮新增）：
  accepted / result_fenced / executor_cancel_requested（当前恒 False
  ——内核外无执行器可信号）/ executor_cancel_confirmed /
  external_effects_possible（恒 True——provider/执行器侧副作用
  无法撤销）
- **取消是逻辑取消**：结果栅栏（绝不投递）+ 结构化唤醒通知
  {error, cancelled, request_id}；本地进程可物理终止（超时路径）；
  远程/LLM 无法从内核中止外部执行（触发条件见 OI-001 / v0.8 P2-10）
- LLM 措辞修正：可逻辑取消 + 结果 fencing，**不保证撤销 provider
  端处理、费用或数据传输**

## 7. 已知限制（诚实声明）

1. apply_patch 按行序列处理（'\n' join，无尾换行保证）——编辑工具
2. run_tests 继承宿主环境/PATH；无只读挂载/网络拒绝/资源上限
   （LOCAL_PROCESS，非沙箱）
3. git 工具/run_tests 在 Act 期执行，看到**已提交**状态
4. 取消不中止外部执行器（逻辑取消；物理化见 v0.8 P2-10）
5. 远程工具执行器仍为外部 harness；插件注册/执行器分级未实现
   （v0.8 P1-4/5）
6. Executor Admission 未实现（无 worker 池，v0.8 P1-4）
7. LLM budget 仅覆盖并发维度（concurrency + 本 tick 复查）；token/
   cost/request_count/wall_time 分列预算见 v0.8 P2-11
