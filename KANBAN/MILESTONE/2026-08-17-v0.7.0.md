## 1. ToolManifest + OperationPolicy（P1-1，f77846f）

- `ToolManifest`（frozen dataclass）：name/version/schema/capabilities/
  effect_types/execution_class（PURE/READ_ONLY/LOCAL_DETERMINISTIC/
  STAGED_MUTATION/SANDBOXED_PROCESS/EXTERNAL_IRREVERSIBLE）/
  deterministic/idempotent/reversible/requires_network/filesystem_scopes/
  max_runtime_ms/max_output_bytes/supports_cancel/requires_approval/
  retry_policy
- 注册即校验（ToolManifestError）：必填字段；执行类一致性（READ_ONLY
  不得声明副作用、STAGED_MUTATION 必须声明 ≥1、PURE 必须确定性、
  EXTERNAL_IRREVERSIBLE 必须不可逆）；effect_type / filesystem_scope
  成员校验
- `OperationPolicy`（默认拒绝）：白名单、审批、网络、文件系统作用域、
  墙钟/输出上限、不可逆拒绝；`requires_approval ⊆ allowed` 注册校验
- `ToolRegistry`：register_manifest / register_handler(manifest=) /
  policy gate（policy_denied / requires_approval 错误码）；策略启用时
  无 manifest 的工具一律拒绝（默认拒绝）
- 27 个测试（test_tool_manifest.py）

## 2. 两阶段 Validate 强化（P1-2，27835fc）

原则固化为注释/SPEC/docstring（并有测试断言）：

```text
PreValidate（Phase 6）  — "是否允许尝试？"
CommitValidate（Phase 8）— "现在是否仍可提交？"
```

- PreValidate 新增：Check 1d 工具 manifest + 操作策略（缺 manifest /
  policy_denied / requires_approval 均拒绝并审计 PERMISSION_DENIED）；
  Check 4 task 有效性（引用的 task 必须存在、deadline 未过）
- Act 新增：LLM budget 提交时复查（registry 在飞 + 本 tick 提交数），
  封堵 PreValidate→提交窗口
- CommitValidate 新增：TransactionBuffer.validate 的 check_task 回调——
  TASK_UPDATE 必须指向存在、未取消、未终态、未过 deadline 的 task；
  失败为 effect 局部 FAILED，**绝不触发整 tick 回滚**（同时保护
  update_status 的非法转换路径）
- 14 个新测试（test_two_phase_validate.py）；mock 远程工具改为声明
  EXTERNAL_IRREVERSIBLE manifest（tests/tool_helpers.py）

## 3. 受限工具（P1-3，24ff837）——先于 Bash

| 工具 | execution_class | 语义 |
|---|---|---|
| apply_patch | STAGED_MUTATION | 严格 unified-diff 引擎：格式校验 + 精确上下文匹配（冲突检测）+ 新文件/删除文件 + hunk 重叠拒绝；Act 期对**冻结视图**校验，stage FILE_PATCH，Commit 期落地，file_previous 回滚 |
| run_tests | SANDBOXED_PROCESS | `uv run pytest`，manifest 超时/输出上限 |
| git_diff | READ_ONLY | 只读 `git diff`，workspace 作用域 |
| git_status | READ_ONLY | 只读 `git status --short` |

- `patch_ops.py`：ParseError(conflict) 区分格式错误与上下文冲突；
  错误码 invalid_patch / patch_conflict
- `sandbox_tools.py`：**list 命令强制**（str 命令会被 Popen 走 shell，
  显式拒绝）；进程组超时终止（start_new_session + killpg，无孤儿）；
  输出截断（带 [truncated N bytes] 标记）；固定 cwd。声明 SANDBOXED_
  PROCESS 的 manifest 记录**实际已强制**的约束，完整沙箱协议
  （只读挂载/网络拒绝/资源上限）属 OI-001
- 29 个新测试（test_restricted_tools.py）

## 4. 工具超时与取消（P1-4，18f6964）

- 本地沙箱工具超时 → 结构化 `error_code="tool_timeout"` + TOOL_TIMEOUT
  审计（进程组已由 sandbox_tools 终止）
- `Simulation.cancel_operation(request_id, agent_id=)`：
  - TOOL_REQUEST 需 manifest supports_cancel；LLM 请求恒可取消
    （无外部副作用，丢弃挂起响应即安全）
  - 唤醒等待中的 agent，携带结构化 **取消通知**
    `{error, cancelled, request_id}`——绝不投递结果
  - OP_CANCELLED 审计；已取消 op 从注册表移除；迟到的结果被
    complete() 栅栏（从未发布）
  - 非在飞/非本 agent/不支持取消 → 拒绝（返回 None）
- 9 个新测试（test_tool_timeout_cancel.py）

## 6. 已知限制（诚实声明）

1. apply_patch 按行序列处理（'\n' join，无尾换行归一化保证）——编辑工具，
   非字节精确归档工具
2. run_tests 继承宿主环境变量与 PATH；无只读挂载/网络拒绝（OI-001 前置
   未完成前保持声明透明）
3. git 工具与 run_tests 在 Act 期执行，看到的是**已提交**状态（本 tick
   的 staged 写入在 Commit 才落地）
4. 取消是"通知 + 弃结果"，不中止外部执行器（外部已发出的请求无法撤回）
5. 远程工具执行器仍为外部 harness（FakeToolExecutor 模式）；manifest
   是契约，注册器未实现（v0.8+ 插件注册表）
