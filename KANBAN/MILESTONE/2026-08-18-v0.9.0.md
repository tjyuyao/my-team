### T4: Unified TickJournal（7c832d7）

单一事实源：append-only Journal 记录每个 tick 的完整生命周期。

- **新模块** `journal.py`：`TickRecord`（tick/epoch/snapshot_hash/
intents/validation/effects/pending_ops/outbox/audit_events/status）+
`TickJournal`（start_tick/finalize/current_record）
- **AuditLog 投影**：`AuditLog.record()` 内部委托写入当前 TickRecord
（零调用点改动）
- **_phase_commit 写入**：成功→记录 effects + pending_ops + outbox；
rollback→记录 aborted + rolled-back effects
- **持久化**：`_collect_state` 新增 `tick_journal` 组件；
`_restore_state` 先恢复 Journal，从 Journal 重建 AuditLog
- 新增 `tests/test_tick_journal.py`（18 tests）

### T5: SimulationRuntime + LLM Dispatcher + HTTP Control Plane（d813037）

系统从"同步紧循环"变为可实时运行、可调速、可外部控制的服务。

- **SimulationRuntime**（`runtime.py`）：wall-clock tick loop + start/
stop/pause/resume/step + set_tick_duration + status dict。后台线程
daemon，`time.sleep(tick_duration)` 实现 wall-clock pacing
- **LLM Dispatcher**（`llm_dispatcher.py`）：worker 线程轮询 SUBMITTED
LLM op，调用 LLMGateway，写回结果。替代 FakeLLMProvider.advance()
手动模式
- **HTTP Control Plane**（`control_plane.py`）：stdlib http.server，
GET /status、POST /start|pause|resume|step、POST /email、
GET /agents|tasks。CORS 支持
- **接线**：`run_tick()` 开始调用 `apply_pending_duration_changes()`
- 新增 `tests/test_runtime.py`（12）、`tests/test_llm_dispatcher.py`
（6）、`tests/test_control_plane.py`（7）= 25 tests

### T6: ContextCompiler（3beeaa2）

角色化观察与 token-budgeted briefing。

- **新模块** `context_compiler.py`：`ObservationPolicy`（sections/
task_scope/kb_injection/max_tokens）+ `ContextCompiler.compile()`
- **三套默认策略**：
  - root：mission + task_tree_summary + kpi_dashboard + escalations
    + pending_decisions + emails + kb_snapshot（ALL scope, 8k tokens）
  - manager：task_tree_summary + task_detail + emails + kb_snapshot
    （SUBTREE scope, 6k tokens）
  - worker：task_detail + emails + workspace_files + kb_snapshot
    （FOCUS scope, 4k tokens）
- **Token budget**：email body 超限时截断
- **集成**：`_phase_observe()` 使用 ContextCompiler 替代直接
  snapshot 转换（向后兼容）
- 新增 `tests/test_context_compiler.py`（17 tests）

## 已知限制

1. **LLM Dispatcher 依赖 LLMGateway**：dispatcher 调用 `gateway.complete()`，
   需要有效的 provider 配置。无 provider 时 dispatcher 静默跳过
2. **ContextCompiler token 估算粗糙**：~4 chars/token 的简单估算，
   未考虑 tokenizer 差异
3. **HTTP Control Plane 无认证**：内部服务设计，生产环境需加 auth
4. **simulation.py 仍为最大模块**（3,624 行；非空行口径占源码 27.5%，
   全行口径 25.6%）——TickJournal 集成增加了约 100 行，核心复杂度未简化
5. **llm_gateway.py 覆盖率最低**（51% combined / 54% line，81 语句仅 44
   覆盖）——LLM 网关是 Dispatcher 的直接依赖，回落/错误分支基本未测，
   应为 v0.10 测试补强重点（初版误标为 task_tree，本版订正）
6. **task_tree.py 覆盖率仍低**（63% line / 58% combined）——部分分支路径
   未充分测试
7. **Authority 模块**（`authority.py`）存在但未完全集成到 simulation——
   该模块来自范围内 v0.11 提交 c158a4a，其仿真接线在 v0.11 E1/E2
