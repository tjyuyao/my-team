## P1 完成情况

### 1. Pending ops + outbox 持久化闭环（P1-1/2，f941f52）

- 机制（save/load 全量序列化）v0.6.0 已存在；本版本补齐并测试
  **跨重启继续执行**：SUBMITTED/PENDING op 保存 → 重启 → 外部执行器
  完成 → Ingest 投递（state_epoch fencing 跨重启，含"重启后 epoch
  前进 → 旧 epoch 结果被 Fence 1 丢弃"）
- **outbox dispatch 缺陷修复**：dispatch 原先嵌在 EMAIL_SEND effect
  的 apply 分支内——没有新邮件 effect 的 tick 永远不会派发遗留
  COMMITTED 条目（重启续投、重试退避）。现改为 commit 成功后**每
  tick 无条件执行**；回滚丢弃本 tick 已 commit 未派发的条目
  （rollback_committed）——邮件只在完整 commit 成功后创建

### 2. ToolRequest / ToolResult 契约（P1-3，ee3e8ca）

- `ToolRequest`（工具协议）：request_id / agent_id / task_id /
  tool_name / tool_version / **manifest_hash** / **input_hash** /
  state_epoch / **workspace_version**（冻结文件视图哈希）/ created /
  deadline tick / arguments——**全部由内核在 Act 注入**，执行器或
  插件永不自指身份字段
- `ToolResultContract`：request_id 关联校验 / status / exit_code /
  stdout/stderr / data / output_hash / **declared/observed/possible
  effects 区分** / executor_cancel_confirmed
- `ToolManifest.manifest_hash`：全契约字段的 sha256，版本或任一
  字段变更即变
- Ingest 投递审计携带 manifest_hash/tool_version/input_hash/
  output_hash（回放上下文）

### 3. Executor Admission + 执行器分级（P1-4/5，083f3cc）

- `ExecutorTier`：TRUSTED_IN_PROCESS / UNTRUSTED_OUT_OF_PROCESS /
  SANDBOXED_OUT_OF_PROCESS；manifest execution_class → 所需 tier 映射
- **Phase 9 dispatch**（run_tick 文档本就承诺、此前从未实现的

### 5. sandboxed_python L0/L1（P1-7，efc800a）

按设计评审定稿（SPEC §8.7「执行等级」）落地，**诚实分类**：

- `python_compute`（L0）：子进程 + `-I` 隔离模式 + 受限 builtins
  （无 open/exec/eval/globals…）+ import 白名单（stdlib 子集）；
  JSON 输入 → 结构化 result（JSON 序列化校验）；超时/截断/进程组
  终止
- `python_transform`（L1）：临时 sandbox 工作区——input/ 只读副本
  （**来自冻结视图**，非活文件系统）、output/ 可写；产物以
  artifact manifest（path/hash/size/content）返回，**进入正式工作区
  只能经 agent 自己带 base_hash 的 staged 写入**（复用 FILE_PATCH
  复查机制）
- **L0/L1 是防意外（幻觉/错参/死循环），不是防恶意逃逸的安全边界**
  （object.__subclasses__ 等原理上可绕过）——manifest possible_
  side_effects 如实披露（possible_fs_access）；安全边界从 L2
  （SANDBOXED_PROCESS）开始，当前无内置工具声明该级别
- 模式 A（code + inputs）先行；模式 B（entrypoint + 文件项目）延后

### 6. 取消物理化（P2-10，efc800a）

### 7. 跨进程恢复（P2-9，12b9b9f）

- 修复缺口：Ingest 原先只处理 TIMED_OUT/COMPLETED——FAILED op
  （worker 崩溃）永久滞留。现 FAILED op 被消费 + 结构化
  {error, failed, request_id} 唤醒 + 审计
- 测试：崩溃 → 唤醒 → 以新 request_id 重试（旧 id 被 seen-history
  栅栏）；三次 save/load 循环状态与审计收敛、无重复投递

## 已知限制（诚实声明）

1. L0/L1 python 不是安全边界（防意外不防恶意逃逸）——见
   python_worker.py docstring 与 manifest 披露
2. TRUSTED_IN_PROCESS 执行同步阻塞 tick：tick 墙钟 ≈ 工具墙钟
   （≤ manifest max_runtime_ms）
3. SANDBOXED_OUT_OF_PROCESS 无内置执行器（run_tests 真隔离 =
   P2-7，开放）
4. python_transform 产物不自动合并进工作区——agent 中介的 staged
   写入（设计如此，防静默覆盖）
5. 取消对远程/LLM op 仍为逻辑取消（外部 harness 不可达）
6. 持久化 schema 未迁移工具（SCHEMA_VERSION=1 不变；新增字段均有
   默认值，旧存档可加载）
7. P2-8 Snapshot 矩阵、P2-11 token/cost 预算未做（见计划）
