## Executive Summary

v0.5.0 proves the **complete event-driven loop works end-to-end** across multiple ticks. The three major deliverables:

1. **Tool handlers registered** — `read`, `write`, `ls`, `send_email`, `delegate` all go through `ToolRegistry.execute()` → handler → staged effects (writes) or direct execution (reads)
2. **`_phase_commit` implemented** — validates effects (permission, lock, version), resolves conflicts deterministically, applies committed effects atomically (file writes, email queueing, task creation)
3. **10 multi-tick E2E tests** proving: Root → delegate → email delivered → research activates → sends result → email delivered to root

The loop that was previously theoretical now has a tested, working implementation:

```text
Event wake → Agent activation → Decision → Tool execution
→ Validation → Commit → Effect application → Event publish → Next-tick wake
```

## What Changed

### 1. Tool Handlers Registered (`simulation.py`)

Five tool handlers registered in `_initialize()` via `_register_tool_handlers()`:

| Handler | Type | Behavior |
|---------|------|----------|
| `read` | Direct | Reads file from private workspace, returns content |
| `ls` | Direct | Lists directory entries in private workspace |
| `write` | Staged | Stages `FILE_WRITE` effect in TransactionBuffer |
| `send_email` | Staged | Stages `EMAIL_SEND` effect in TransactionBuffer |
| `delegate` | Staged | Stages `TASK_CREATE` + `EMAIL_SEND` effects |

Write tools no longer execute directly — they stage effects that are committed atomically in Phase 8.

### 2. `_phase_commit` Implemented (`simulation.py`)

Replaced the stub with a real commit pipeline:

```text
1. Validate effects (permission, lock, version checks)
2. Resolve conflicts (deterministic, by agent_id)
3. Commit all validated effects
4. Apply committed effects to subsystems:
   - FILE_WRITE → write to private workspace
   - EMAIL_SEND → create email in MailSystem
   - TASK_CREATE → create task in TaskTree (status=ASSIGNED)
5. Record TRANSACTION_COMMIT audit events
```

Key design decisions:
- **Permission check**: only enforced for KB operations (`kb_write`, `kb_create`, `kb_delete`), not private workspace writes
- **Lock check**: only enforced for shared KB resources (`shared-kb/`, `project/`), not private files
- **Task status**: created tasks default to `ASSIGNED` (not `DRAFT`), matching SPEC §4.4 delegation semantics
- **Buffer cleanup**: `TransactionBuffer.clear()` called after commit in `run_tick()`

### 3. Multi-Tick E2E Tests (`tests/test_e2e_multitick.py`, new)

  Phase 2 (Deliver): no emails to deliver
  Phase 3 (Schedule): agent.root BOOTSTRAP → ready
  Phase 4-5 (Observe/Decide): root decides to delegate
  Phase 6 (Validate): delegate action passes (research is direct child)
  Phase 7 (Act): delegate handler stages TASK_CREATE + EMAIL_SEND
  Phase 8 (Commit): task created (assigned), email queued (deliver_at_tick=1)

  Phase 4-5 (Observe/Decide): research decides to send result email
  Phase 6 (Validate): send_email passes (research has send_email tool)
  Phase 7 (Act): send_email handler stages EMAIL_SEND
  Phase 8 (Commit): email queued (deliver_at_tick=2)

## Known Limitations

### What's Fixed in v0.5.0

1. ~~`_phase_commit` was a stub~~ → Now implements validate → resolve → commit → apply pipeline
2. ~~No tool handlers registered~~ → All 5 tools go through `ToolRegistry.execute()`
3. ~~No multi-tick E2E~~ → 10 tests proving the complete loop across ticks
4. ~~SharedKB dual entry risk~~ → All writes staged through TransactionBuffer (KB direct path still exists but is not used by tool handlers)

### What Remains Open

1. **SharedKB direct `write()` still exists** — not removed, just not used by tool handlers. A future refactor should enforce single write entry point.
2. **LLM calls are synchronous** — `WAITING_FOR_LLM` is modeled but not used for async provider latency. One slow LLM call blocks the entire tick.
3. **BoundedMicroLoop doesn't re-observe** — second LLM round uses the original snapshot.
4. **No persistence** — all state is in-memory. Process restart loses everything.
5. **No rollback on commit failure** — if one effect fails during application, previously committed effects in the same tick are not rolled back.
6. **Email delivery is in-process** — no outbox persistence, no idempotent delivery, no crash recovery.
7. **No real LLM E2E** — all tests use `ScriptedAgent` with deterministic plans, not real LLM calls.
