## 3. What's New in v0.2.0

### 3.1 Simulation Integration Layer (`simulation.py`)

The `Simulation` class ties all subsystems together into a runnable system:

```python
sim = Simulation.from_config_file("configs/team.json")
results = sim.run(max_ticks=10)
```

**Initialization:**
- Creates mailboxes for all agents
- Initializes private workspaces
- Registers tool permissions per agent
- Creates appropriate AgentRuntime per agent role
- Sets up HumanControl, DelegationProtocol, AuditLog

**Tick execution (7 phases):**
1. **Freeze** — Build global state snapshot
2. **Deliver** — Route emails to inboxes
3. **Observe** — Each agent reads from frozen snapshot
4. **Decide** — Each agent generates ActionPlan
5. **Act** — Execute actions through ToolRegistry
6. **Commit** — Atomic state update
7. **Audit** — Record all events

### 3.2 Agent Runtime Protocol (`agent_runtime.py`)

Defines the contract all agent implementations must satisfy:

```python
class AgentRuntime(Protocol):
    def observe(self, snapshot: dict) -> AgentObservation: ...
    def decide(self, observation: AgentObservation) -> ActionPlan: ...
    def act(self, plan: ActionPlan, context: ActionContext) -> list[ActionResult]: ...
```

**Built-in implementations:**
- `RootAgent` — restricted to {read, write, ls, delegate}
- `ManagerAgent` — can delegate + send_email
- `SubAgent` — base tools + extensible extras
- `BaseAgent` — subclassable default

**ToolContext (frozen dataclass):**
- Binds `agent_id` to every tool call
- Immutable — agents cannot modify their identity
- Created only by the system, never by agents

**ToolRegistry:**
- Central permission enforcement
- `authorize()` checks agent has tool permission
- `execute()` validates + runs handler
- Returns `ToolResult` on failure (never raises for permission errors)

### 3.3 Atomic Transaction Buffer (`transaction.py`)

Implements the full Commit phase model from SPEC §8.2:

```
Act → stage effects → validate → resolve conflicts → commit/rollback
```

**StagedEffect lifecycle:**
```
STAGED → VALIDATED → COMMITTED
                  → FAILED (validation error)
COMMITTED → ROLLED_BACK (on partial failure)
```

**Conflict resolution (deterministic):**
- Same resource, same agent: keep by effect_id order
- Same resource, different agents: alphabetical by agent_id
- Lock holder wins over non-holder

**Validation checks:**
- Version check (optimistic concurrency)
- Lock check (exclusive access)
- Permission check (agent authorization)

### 3.4 Identity Enforcement (`identity.py`)

Central service preventing identity spoofing:

```python
enforcer = IdentityEnforcer(tool_registry)

# System creates context — agents cannot
ctx = enforcer.create_tool_context("agent.research")

# System sets from_agent from context
email = enforcer.wrap_email_creation(ctx, to=["agent.root"], ...)

# Spoofing detected and rejected
enforcer.validate_sender(ctx, "agent.root")  # raises SpoofedSenderError
```

**Protections:**
- `ToolContext` frozen dataclass — immutable after creation
- `IdentityEnforcer` is the only place ToolContext is created
- Email `from_agent` set from context, not caller
- File/KB operations bound to context.agent_id
- Config modification prevention

### 3.5 Email Sorting Fix (SPEC §13.3)

Updated `_sort_key` in `mailbox.py`:

```python
def _sort_key(email: Email) -> tuple[int, int, int, str]:
    return (
        type_rank,          # 0=system_notice, 1=human_message, 2=other
        priority_rank,      # urgent=0, high=1, normal=2, low=3
        created_at_tick,    # earlier first
        email_id,           # deterministic tiebreak
    )
```

### 3.6 End-to-End Delegation Tests

8 tests verifying the complete delegation flow:

1. **Full flow** — Root→Research→WebResearch→shared KB→result
2. **Direct child only** — WebResearch cannot delegate to Root
3. **Deadline constraint** — Sub-task deadline ≤ parent deadline
4. **Private space isolation** — Cross-agent access denied
5. **Shared KB permissions** — Unauthorized path rejected
6. **Task tree integrity** — Parent-child relationships verified
7. **Email delivery timing** — Correct tick delivery
8. **Lock exclusivity** — Concurrent lock acquisition blocked

## 10. Recommendations for v0.3.0

### Priority P2 (High Value)

1. **LLM Agent Integration** — Implement a concrete `AgentRuntime` that calls an LLM in `decide()` and executes tool calls in `act()`. This is the core of making agents actually intelligent.

2. **Cross-process Persistence** — Add JSON/SQLite serialization for `Simulation` state, enabling pause/resume across process restarts.

3. **Lock Token Mechanism** — Add UUID tokens to locks so only the holder can release, preventing stale-holder attacks.

4. **Timeout Checker Phase Binding** — Fix `TimeoutChecker` to run at a specific tick phase (e.g., after Commit) with clear boundary semantics.

### Priority P3 (Nice to Have)

5. **REST API** — Implement SPEC §16 HTTP endpoints for external control.

6. **Web UI** — Real-time dashboard showing agent states, task tree, email flow.

7. **Deterministic Replay with LLM** — Save model name, prompt, seed, response for exact replay.
