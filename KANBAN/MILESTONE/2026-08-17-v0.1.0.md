## 一、项目概览

My-Team 是一个基于层级委派和异步通信的多智能体协作模拟平台。系统采用离散时间步驱动，Agent 之间通过 E-mail 协作，共享知识库支持权限控制和互斥锁。

**核心技术栈:**
- 语言: Python 3.10+
- 数据模型: Pydantic v2
- 包管理: uv
- 构建: hatchling
- 测试: pytest

## 四、模块详解

### Phase 1: 基础运行时

#### 4.1 Agent 组织树 (`agent_tree.py` — 367 行)

静态组织树的定义、加载和校验。

**核心功能:**
- 从 JSON 配置文件加载 Agent 树
- 不变量校验: 无重复 ID、无环、单根、父子一致
- 树遍历: `get`、`children`、`parent`、`siblings`、`is_ancestor`、`ancestors`、`depth`、`subtree_ids`
- 委派权限检查: `can_delegate_to`
- 序列化: `to_dict` / `from_dict` / `from_config_file`

#### 4.2 Agent 状态机 (`agent_state.py` — 332 行)

Agent 生命周期状态机，含转换表和审计日志。

**状态枚举:**
```
created → initialized → ready → running → terminated
                          running 子状态:
                          idle / processing / waiting / blocked / paused / failed
```

**核心功能:**
- 转换表: 定义每个状态的合法目标
- `transition()`: 通用状态转换，非法转换抛出 `InvalidTransitionError`
- 便捷方法: `initialize()`、`mark_ready()`、`start()`、`begin_processing()`、`wait()`、`block()`、`pause()`、`fail()`、`recover()`、`terminate()`
- `AuditLog`: 追加式审计

#### 4.3 私人工作空间 (`private_store.py` — 157 行)

每个 Agent 的隔离工作空间。

**目录结构 (SPEC §5.1):**
```
private/{agent_id}/
  inbox/       # 收件箱
  outbox/      # 发件箱
  workspace/   # 工作文件
  memory/      # 私密记忆
  task_state/  # 任务状态
  logs/        # 运行日志
```

**访问控制:**
- `resolve_path()`: 路径解析（仅阻止 `../` 穿越，见 §八 已知差距）
- `check_access()`: 确保 Agent 只能访问自己的空间
- `get_storage_usage()`: 存储配额统计

#### 4.4 文件操作工具 (`file_ops.py` — 343 行)

Agent 可使用的基础文件操作。

| 工具 | 说明 |
|------|------|
| `read` | 读取文件内容 |
| `write` | 写入文件（自动创建父目录） |
| `ls` | 列出目录内容 |

**约束:**
- 所有操作经过 `PrivateStore.resolve_path()` 权限检查
- 单步写入大小限制（默认 10MB）
- Agent 总存储配额（默认 512MB）
- 所有操作记录到 `FileOpsAuditLog`

#### 4.5 时间步引擎 (`tick_engine.py` — 454 行)

离散时间步驱动的模拟时钟。

**7 阶段执行器 (SPEC §8.2):**

| Phase | 名称 | 功能 | 实现状态 |
|-------|------|------|----------|
| 1 | Freeze | 冻结全局状态快照 | ✅ 已实现 |
| 2 | Deliver | 投递满足条件的邮件 | ✅ 已实现 |
| 3 | Observe | Agent 从快照读取输入 | ⚠️ 骨架（无真实 Agent 读取） |
| 4 | Decide | Agent 生成动作计划 | ⚠️ 骨架（回调接口，无 LLM） |
| 5 | Act | 并行执行动作 | ⚠️ 骨架（无真实执行） |
| 6 | Commit | 原子提交状态变更 | ⚠️ 部分（邮件入队已实现，完整事务未实现） |
| 7 | Audit | 记录审计事件 | ✅ 已实现 |

**核心功能:**
- `advance(count)`: 推进 N 个 tick
- `TickSnapshot`: 读一致性快照机制
- `pause()` / `resume()`: 暂停恢复
- `register_phase_handler()`: 可扩展的阶段回调

### Phase 2: E-mail 协作

#### 4.6 邮箱系统 (`mailbox.py` — 248 行)

Agent 间异步通信的核心。

**组件:**
- `Mailbox`: 每个 Agent 的 inbox/outbox
- `MailSystem`: 中央邮件路由

**邮件排序 (SPEC §13.3):**
当前实现按优先级 + 创建时间 + email_id 排序。
⚠️ 未完全符合 SPEC 排序规则（缺少 system_notice/human_message 优先级、缺少 deadline_tick 排序，见 §八）。

**邮件状态:**
```
queued → delivered → read
```

**邮件类型 (13 种):**
delegation / acceptance / progress / question / answer / result / review_request / review_result / failure / blocked / cancellation / human_message / system_notice

#### 4.7 任务树 (`task_tree.py` — 270 行)

动态任务树的 CRUD 和状态管理。

**任务状态 (13 种):**
```
draft → assigned → accepted → in_progress → submitted → reviewing → completed
                          ↘ blocked      ↘ waiting_for_children
                          ↘ failed       ↘ cancelled / expired
```

**核心功能:**
- `create()` / `get()` / `update_status()`: 任务 CRUD
- `children()` / `parent()` / `ancestors()` / `subtree()`: 树遍历
- `get_expired_tasks()` / `expire_task()`: 过期检测

⚠️ 未验证的不变量: 父任务取消后子任务处理、子任务全部完成后父任务自动状态转换（见 §八）。

#### 4.8 委派协议 (`delegation.py` — 354 行)

Agent 间通过 E-mail 的完整委派流程。

**委派流程 (SPEC §7):**
```
上级 Agent 发送 delegation 邮件
  → 子 Agent 发送 acceptance 或 failure 邮件
  → 子 Agent 执行（可继续向下委派）
  → 子 Agent 发送 result 邮件
  → 上级 Agent 汇总审查
```

**API:**
- `delegate()` / `accept()` / `reject()`
- `report_progress()` / `report_blocked()`
- `submit_result()` / `cancel()` / `check_expired()`

**已验证约束:**
- ✅ 只能委派给直接子节点 (`NotDirectChildError`)
- ✅ 子任务截止时间不超过父任务 (`DelegationDeadlineError`)
- ✅ 委派深度限制 (`DelegationDepthError`)

### Phase 3: 共享知识库

#### 4.9 共享知识库 (`shared_kb.py` — 511 行)

集成权限、锁、版本控制的统一共享存储。

**三大子系统:**

**① 路径权限控制 (`PermissionEngine`)**
- 10 种操作: list / read / create / write / append / rename / delete / lock / unlock / publish
- 通配符匹配: `project/research/*`
- 最小权限原则

**② 排他锁 (`LockManager`)**
- acquire / release / renew / check_expired
- 默认租约 4 ticks
- 过期自动释放 + 审计日志

⚠️ 已知差距: 无锁 token 机制，旧持有者可能误释放新锁（见 §八）。

**③ 版本控制 (`VersionControl`)**
- 乐观锁: 写入时携带读取时的版本号
- 版本不匹配拒绝提交: `VersionConflictError`

**完整写入流程 (SPEC §6.3):**
```
获取锁 → 读取当前版本 → 修改本地副本 → 写入新版本
→ 执行一致性检查 → 提交版本 → 释放锁
```

⚠️ 仅 `write()` 方法经过完整流程。`delete`、`append`、`rename` 等操作未强制持锁（见 §八）。

#### 4.10 审计日志 (`audit.py` — 174 行)

25+ 事件类型的追加式审计日志。

**查询接口:**
- `for_agent()` / `for_event_type()` / `for_tick()`
- `failures()` / `since()` / `last()`

## 八、已知差距

### 8.1 系统集成层缺失

当前各模块是独立组件，缺少 `Simulation` 类将它们组合为可运行系统。需要：

```python
class Simulation:
    agent_tree: AgentTree
    mail_system: MailSystem
    task_tree: TaskTree
    shared_kb: SharedKB
    tick_engine: TickEngine
    runtimes: dict[str, AgentRuntime]
```

### 8.2 Agent Runtime 缺失

`TickEngine` 的 Decide/Act 阶段目前只有回调接口，无真实 Agent 执行：

```python
class AgentRuntime(Protocol):
    def observe(self, snapshot: TickSnapshot) -> AgentObservation: ...
    def decide(self, observation: AgentObservation) -> ActionPlan: ...
    def act(self, plan: ActionPlan, context: ActionContext) -> list[ActionResult]: ...
```

### 8.3 身份强制缺失

邮件 `from_agent` 字段可由调用方任意设置。需要 `ToolContext` 绑定身份：

```python
class ToolContext:
    agent_id: str
    simulation_id: str
    tick: int
```

系统侧必须从 context 获取身份，忽略请求体中的 `from_agent`。

### 8.4 原子提交未实现

当前 `Commit` 阶段仅处理邮件入队，缺少：
- 动作事务 buffer
- 资源冲突确定性解决
- 部分失败回滚
- 多 Agent 并发提交的原子性保证

### 8.5 邮件排序不符合 SPEC §13.3

SPEC 建议排序:
1. 系统通知
2. 人类邮件
3. 高优先级邮件
4. 截止时间更近的任务
5. 创建时间
6. email_id 字典序

当前实现仅按优先级 + 创建时间 + email_id 排序。

### 8.6 跨进程持久化未实现

`PrivateStore`、`AuditLog`、`VersionControl` 等均为进程内对象，不支持：
- 进程重启后恢复
- 模拟暂停后重新加载
- 审计日志持久存储

### 8.7 路径安全不完整

`resolve_path()` 仅阻止 `../` 穿越，未处理：
- 符号链接指向其他 Agent 目录
- TOCTOU 竞态
- Unicode 规范化绕过

### 8.8 锁租约语义不完整

缺少：
- 锁 token 机制（防旧持有者误释放新锁）
- 暂停期间锁是否继续消耗模拟时间
- `lease_until_tick` 边界语义
- 同一 Agent 重复 acquire 的幂等性

### 8.9 超时检查执行位置未固定

`TimeoutChecker` 未绑定到固定 tick phase，边界 tick 行为不确定：
- `deadline_tick == current_tick` 时是否仍可提交
- 超时和成功提交同时发生时谁优先
- Agent paused 时任务是否继续过期

### 8.10 任务树不变量验证不完整

未验证：
- 父任务取消后子任务处理策略
- 子任务全部完成后父任务自动状态转换
- 子任务 owner 必须是委派者的直接子 Agent

### 8.11 邮件投递时序未明确规定

未明确：
- tick t 发送的邮件最早在 tick t 还是 t+1 投递
- `deliver_at_tick` 是否允许早于 `created_at_tick`
- 同一 tick 内新发送的邮件是否可被其他 Agent 读取

### 8.12 确定性回放不完整

`DeterministicReplay` 使用 `copy.deepcopy`，但：
- 不可序列化，不可跨进程
- 不支持 LLM 输出的确定性重放
- 不保证外部文件状态一致

### 8.13 Pydantic 模型可变性

`Email`、`AgentConfig` 等模型未设置 `frozen=True`，可通过 `model_copy(update=...)` 修改身份字段。

## 十、结论

本版本（v0.1.0）完成了 SPEC 定义的 21 个实现任务，实现了核心数据模型、组织树、状态机、私人空间、文件操作、邮箱、任务树、委派协议、共享知识库（权限+锁+版本）、审计日志、人类控制和可靠性基础组件。

**已完成:** 数据模型、独立组件、协议校验、Tick 骨架
**未完成:** Simulation 集成、Agent Runtime、端到端运行、原子提交、跨进程持久化、REST API

当前版本适合作为 **核心模块实现里程碑**，不适合作为 **SPEC 全部实现完成** 或 **production-ready release**。
