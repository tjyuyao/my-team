## 一、项目概览

My-Team 是一个基于层级委派和异步通信的多智能体协作模拟平台。系统采用离散时间步驱动，Agent 之间通过 E-mail 协作，共享知识库支持权限控制和互斥锁。

**核心技术栈:**
- 语言: Python 3.11+
- 数据模型: Pydantic v2
- 包管理: uv
- 构建: hatchling
- 测试: pytest

## 三、模块详解

### Phase 1: 基础运行时

#### 3.1 Agent 组织树 (`agent_tree.py` — 367 行)

静态组织树的定义、加载和校验。

**核心功能:**
- 从 JSON 配置文件加载 Agent 树
- 不变量校验: 无重复 ID、无环、单根、父子一致
- 树遍历: `get`、`children`、`parent`、`siblings`、`is_ancestor`、`ancestors`、`depth`、`subtree_ids`
- 委派权限检查: `can_delegate_to`
- 序列化: `to_dict` / `from_dict` / `from_config_file`

**不变量保证 (SPEC §18):**
1. ✅ 一个 Agent 只有一个父 Agent（根除外）
2. ✅ 组织关系不形成环（双向 DFS 检测）
3. ✅ Agent 只能向直接子 Agent 委派

#### 3.2 Agent 状态机 (`agent_state.py` — 332 行)

Agent 生命周期状态机，含转换表和审计日志。

**状态枚举:**
```
created → initialized → ready → running → terminated
                          running 子状态:
                          idle / processing / waiting / blocked / paused / failed
```

**核心功能:**
- 转换表: 定义每个状态的合法目标
- `transition()`: 通用状态转换，非法转换抛出 `InvalidTransitionError`
- 便捷方法: `initialize()`、`mark_ready()`、`start()`、`begin_processing()`、`wait()`、`block()`、`pause()`、`fail()`、`recover()`、`terminate()`
- `AuditLog`: 追加式审计，记录时间戳、Agent ID、源状态、目标状态、tick、原因

#### 3.3 私人工作空间 (`private_store.py` — 157 行)

每个 Agent 的隔离工作空间。

**目录结构 (SPEC §5.1):**
```
private/{agent_id}/
  inbox/       # 收件箱
  outbox/      # 发件箱
  workspace/   # 工作文件
  memory/      # 私密记忆
  task_state/  # 任务状态
  logs/        # 运行日志
```

**访问控制:**
- `resolve_path()`: 安全路径解析，阻止 `../` 穿越攻击
- `check_access()`: 确保 Agent 只能访问自己的空间
- `get_storage_usage()`: 存储配额统计

#### 3.4 文件操作工具 (`file_ops.py` — 343 行)

Agent 可使用的基础文件操作。

| 工具 | 说明 |
|------|------|
| `read` | 读取文件内容 |
| `write` | 写入文件（自动创建父目录） |
| `ls` | 列出目录内容 |

**约束:**
- 所有操作经过 `PrivateStore.resolve_path()` 权限检查
- 单步写入大小限制（默认 10MB）
- Agent 总存储配额（默认 512MB）
- 所有操作记录到 `FileOpsAuditLog`

#### 3.5 时间步引擎 (`tick_engine.py` — 454 行)

离散时间步驱动的模拟时钟。

**7 阶段执行器 (SPEC §8.2):**

| Phase | 名称 | 功能 |
|-------|------|------|
| 1 | Freeze | 冻结全局状态快照 |
| 2 | Deliver | 投递满足条件的邮件 |
| 3 | Observe | Agent 从快照读取输入 |
| 4 | Decide | Agent 生成动作计划 |
| 5 | Act | 并行执行动作 |
| 6 | Commit | 原子提交状态变更 |
| 7 | Audit | 记录审计事件 |

**核心功能:**
- `advance(count)`: 推进 N 个 tick
- `TickSnapshot`: 读一致性快照机制
- `pause()` / `resume()`: 暂停恢复
- `register_phase_handler()`: 可扩展的阶段回调
- `history`: tick 执行历史

### Phase 2: E-mail 协作

#### 3.6 邮箱系统 (`mailbox.py` — 248 行)

Agent 间异步通信的核心。

**组件:**
- `Mailbox`: 每个 Agent 的 inbox/outbox
- `MailSystem`: 中央邮件路由

**邮件排序 (SPEC §13.3):**
1. 优先级（urgent > high > normal > low）
2. 创建时间（更新优先）
3. email_id 字典序

**邮件状态:**
```
queued → delivered → read
```

**邮件类型 (13 种):**
delegation / acceptance / progress / question / answer / result / review_request / review_result / failure / blocked / cancellation / human_message / system_notice

#### 3.7 任务树 (`task_tree.py` — 270 行)

动态任务树的 CRUD 和状态管理。

**任务状态 (12+1 种):**
```
draft → assigned → accepted → in_progress → submitted → reviewing → completed
                          ↘ blocked      ↘ waiting_for_children
                          ↘ failed       ↘ cancelled / expired
```

**核心功能:**
- `create()` / `get()` / `update_status()`: 任务 CRUD
- `children()` / `parent()` / `ancestors()` / `subtree()`: 树遍历
- `get_expired_tasks()` / `expire_task()`: 过期检测
- `get_owner_tasks()`: 按 Agent 查询

#### 3.8 委派协议 (`delegation.py` — 354 行)

Agent 间通过 E-mail 的完整委派流程。

**委派流程 (SPEC §7):**
```
上级 Agent 发送 delegation 邮件
  → 子 Agent 发送 acceptance 或 failure 邮件
  → 子 Agent 执行（可继续向下委派）
  → 子 Agent 发送 result 邮件
  → 上级 Agent 汇总审查
```

**API:**
- `delegate()`: 创建子任务 + 发送委派邮件
- `accept()` / `reject()`: 接受/拒绝委派
- `report_progress()` / `report_blocked()`: 进度/阻塞报告
- `submit_result()`: 提交工作成果
- `cancel()`: 取消任务
- `check_expired()`: 检查过期任务

**约束验证:**
- ✅ 只能委派给直接子节点 (`NotDirectChildError`)
- ✅ 子任务截止时间不超过父任务 (`DelegationDeadlineError`)
- ✅ 委派深度限制 (`DelegationDepthError`)

### Phase 3: 共享知识库

#### 3.9 共享知识库 (`shared_kb.py` — 511 行)

集成权限、锁、版本控制的统一共享存储。

**三大子系统:**

**① 路径权限控制 (`PermissionEngine`)**
- 10 种操作: list / read / create / write / append / rename / delete / lock / unlock / publish
- 通配符匹配: `project/research/*`
- 最小权限原则

**② 排他锁 (`LockManager`)**
- acquire / release / renew / check_expired
- 默认租约 4 ticks
- 过期自动释放 + 审计日志
- 冲突检测: `LockConflictError`

**③ 版本控制 (`VersionControl`)**
- 乐观锁: 写入时携带读取时的版本号
- 版本不匹配拒绝提交: `VersionConflictError`
- 自动递增版本号

**完整写入流程 (SPEC §6.3):**
```
获取锁 → 读取当前版本 → 修改本地副本 → 写入新版本
→ 执行一致性检查 → 提交版本 → 释放锁
```

#### 3.10 审计日志 (`audit.py` — 174 行)

全面的审计日志系统。

**25+ 事件类型:**
- Agent 生命周期: created / initialized / terminated / state_changed
- 委派: sent / accepted / rejected
- 邮件: sent / received / delivered / delivery_failed
- 工具调用: call / result
- 文件操作: read / write / delete
- 共享 KB: create / read / write / delete
- 锁: acquired / released / renewed / expired / conflict
- 权限: denied
- 人类操作: pause / resume / email / config_change
- 时间步: advance / complete
- Agent 失败: failed / retry

**查询接口:**
- `for_agent()` / `for_event_type()` / `for_tick()`
- `failures()` / `since()` / `last()`

### Phase 5: 可靠性

#### 3.12 超时与重试 (`reliability.py` — 340 行)

**RetryManager:**
- 指数退避: `delay = base * multiplier^n`，上限 `max_delay`
- 最大重试次数限制
- 可重试/不可重试失败区分
- 审计日志集成

**TimeoutChecker:**
- 任务超时: 检测 deadline_tick，标记 expired
- 锁超时: 检测 lease_until_tick，自动释放
- `check_all()`: 一次性执行所有超时检查

**FailureType:**
- `tool_error` / `permission_denied` / `timeout` / `resource_exhausted` / `unknown`

#### 3.13 确定性回放 (`reliability.py` — DeterministicReplay)

**保证 (SPEC §2.3, §18.8):**
- 同一输入产生同一输出
- 冲突按 `agent_id + action_type` 确定性排序
- 已完成 tick 不可修改

**API:**
- `save_tick_state()` / `get_tick_state()`: 状态快照（deep copy）
- `save_tick_actions()` / `get_tick_actions()`: 动作日志
- `verify_determinism()`: 对比快照验证确定性
- `resolve_conflicts()`: 确定性冲突解决
- `is_tick_immutable()` / `finalized_ticks`: 不可变性保证

## 七、关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| delegate 语义 | 统一工具（非隐式能力） | 便于权限检查和审计 |
| 循环检测 | 双向 DFS（parent + children） | 单向检测会遗漏反向环 |
| AuditLog 空值 | `is not None` 检查 | `__len__` 导致空实例为 falsy |
| Task EXPIRED | 从所有活跃状态可转换 | 超时可发生在任何阶段 |
| 快照隔离 | `copy.deepcopy` | 防止 Agent 修改影响快照 |
| 版本检查 | 乐观锁（写入时校验） | 无需长时间持锁 |
