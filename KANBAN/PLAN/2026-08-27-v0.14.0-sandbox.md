# v0.14：沙箱 + 信任基础（工作空间治理落地）

## 目标

落实"工作空间与沙箱（治理）"与"信任边界"定案（SPEC.md / AUTHORITY.md）：
进程私密性的机械化 + 信任基础落地。

## 环境前置（已实测，不单开卡）

`bwrap --ro-bind / / --unshare-all true` 本机通过（bwrap + user/pid
namespace 可用，Ubuntu 24.04）。

## 依赖

data-dir-convention → sandbox-wrapper → **unified-identity-home** →
bash-sandbox-adapt → verification；network-declaration 在
unified-identity-home 后（同触 `_bwrap_args`/构造参数链，**串行**）；
outbound-channel 内容已并入 sandbox-wrapper（读侧盖章，不再单列）；
全卡 → verification 收口。落文档任务不入卡（随提交直接对齐，提交前
核对一致性）。

## 验收

- 所有设备进程默认进沙箱：系统路径只读、数据区唯一写根、默认禁网、
  setrlimit 受限、userns/pidns/netns/ipcns 阻断对兄弟/内核进程的信号、
  内存、网络与 System V IPC 攻击（Yama 兜底 ptrace）；沙箱内除继承 fd
  外无跨进程通道；
- 沙箱为固定矩阵（家 + 只读系统），无按 position 的挂载物化；
- 设备持久化数据互不干扰（FS 级强制）；
- bash 命令沙箱内执行且语义正确（cwd/输出落数据区；setsid 逃逸被
  pid namespace + `--die-with-parent` 解决）；
- 出站通道：子进程内不存在可改写的身份字段；伪造 source 尝试被内核
  读侧盖章覆盖；宿主直投路径保留；
- 文档（SPEC/AUTHORITY.md）与代码进度一致；
- 全量回归（tmp/check_*.py + demo）PASS。
