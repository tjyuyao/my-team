# v0.14：沙箱 + 信任基础（工作空间治理落地）

## 目标

落实"工作空间与沙箱（治理）"与"信任边界"定案（SPEC.md / AUTHORITY.md）：
进程私密性的机械化 + 信任基础落地。

## 环境前置（已实测，不单开卡）

`bwrap --ro-bind / / --unshare-all true` 本机通过（bwrap + user/pid
namespace 可用，Ubuntu 24.04）。

## 范围（TODO 卡，共 7 张）

| 卡 | 复杂度 | 内容 |
|---|---|---|
| data-dir-convention | S | 数据区 `data/<identity>` 约定落地（agent workdir / 设备） |
| sandbox-wrapper | L | bwrap 重执行 + userns/pidns + setrlimit + 系统只读 + 数据区写根 + 默认禁网（**固定矩阵，不承载权限**） |
| network-declaration | M | needs_network 显式声明机制（默认禁网） |
| bash-sandbox-adapt | M | bash 设备沙箱语义 + PROTOCOL 更新 |
| outbound-channel | M | 出站通道读侧盖章（source 由内核按队列绑定，子进程无身份字段） |
| sandbox-verification | M | 沙箱+出站通道故事测试 + 全量回归 + 文档一致性收口 |

## 依赖

data-dir-convention → sandbox-wrapper → bash-sandbox-adapt → verification；
network-declaration ∥ sandbox-wrapper（编辑边界不相交：参数通道 vs exec 骨架，见卡内说明）；outbound-channel
在 sandbox-wrapper 后（同触 process 机制，避免冲突）；全卡 → verification
收口。落文档任务不入卡（随提交直接对齐，提交前核对一致性）。

## 验收

- 所有设备进程默认进沙箱：系统路径只读、数据区唯一写根、默认禁网、
  setrlimit 受限、userns/pidns 阻断对兄弟/内核进程的信号与内存攻击；
- 沙箱为固定矩阵（家 + 只读系统），无按 position 的挂载物化；
- 设备持久化数据互不干扰（FS 级强制）；
- bash 命令沙箱内执行且语义正确（cwd/输出落数据区；setsid 逃逸被
  pid namespace + `--die-with-parent` 解决）；
- 出站通道：子进程内不存在可改写的身份字段；伪造 source 尝试被内核
  读侧盖章覆盖；宿主直投路径保留；
- 文档（SPEC/AUTHORITY.md）与代码进度一致；
- 全量回归（tmp/check_*.py + demo）PASS。

## 范围外（明确不做）

- 设备间调用与 origin（AUTHORITY.md 开放问题 11）；
- 运行期状态持久化（开放问题 7）；
- 服务账户 Agent、凭证管理（信任触发条件驱动的未来项）。
