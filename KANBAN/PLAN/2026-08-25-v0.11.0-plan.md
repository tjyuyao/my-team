# v0.11 计划 — 三阶段：pre-agent / agent-impl / post-agent

**Date:** 2026-08-25
**Status:** 进行中

## 一句话定位

v0.11 把 My-Team 从「能跑的引擎」变成「有 Agent 的一人公司操作系统」。
三态重构（内核/设备/Agent）的核心主题是 **Agent 的工具和记忆管理**——
很多东西都统一抽象成了 Agent 的记忆。所以按三个阶段推进：先铺 Agent
落地前的地基，再做 Agent 本身（工具 + 记忆），最后做 Agent 之上的治理
与扩展。

## 三阶段总览

| 阶段 | 一句话 | 卡片 | 状态 |
|---|---|---|---|
| **pre-agent 地基** | Agent 落地前的世界：设备/权限/组织/谓词 | N1a N1b N2 N3 N7 | ✅ 完成 |
| **agent-impl Agent 本身** | Agent 的工具 + 记忆 + 扩展接口 | N1c N4 T17 | 进行中 |
| **post-agent 治理** | 任务治理 + 校验 + 扩展内容 | N5 N8 N9 T13 | 待做 |

> **阶段语义**（2026-08-25 定）：agent-impl 做「Agent 本身的设计」，
> **扩展接口**（MCP、工具注册）属于它本身；post-agent 做「扩展的**内容**」
> ——通过 device 扩展公共资源能力包（场景包等），以及 Agent 之上的治理
> 闭合（审批/升级/裁决/恢复/校验/资产边界）。

## Phase 1 — pre-agent（地基，已完成 ✅）

Agent 落地之前，先把「Agent 之外的世界」搭好。这一阶段已经做完。

| 卡 | 一句话 | 结果 |
|---|---|---|
| N1a 设备协议与 Authority | 设备怎么注册、Authority 怎么布线+注入记忆（**只布线不裁决**，裁决在设备内部） | ✅ |
| N1b 白名单废除 | 删掉硬编码的角色工具白名单，改为两层授予（岗位→工具） | ✅ |
| N2 岗位模型 | Position = 权限主体，Agent 占据岗位即继承边与授权；岗人分离 | ✅ |
| N3 组织架构 + 人类界面 | 上下级/合作边、岗位管理界面；组织架构是 Authority 的子类 | ✅ |
| N7 谓词分级 | 受限表达式的安全分级（纯/有限/可审计） | ✅ |

## Phase 2 — agent-impl（Agent 本身，进行中）

这一阶段做 Agent 的「内心」（记忆）和「双手」（工具面），以及工具扩展
接口。是 v0.11 的核心。

| 卡 | 一句话 | 依赖 | 状态 |
|---|---|---|---|
| **N1c 设备归位** | 把 simulation 里堆的 ~830 行工具处理器拆回各自的设备；私有区文件工具（读写/改文件）归 Agent 私有区 | N1a N1b | 待做 |
| **N4 记忆与注入** | Agent 记忆的**精炼层**：条目 + 召回 + 工作记忆注入 + 整理模式 | N1a N2 | 待做 |
| **原始对话记录层** | Agent 记忆的**原始层**：prompt/response 全文 append-only 落 PrivateStore + 全文检索 | N4-1 | 待做 |
| **T17 MCP** | 把外部 MCP server 的工具接进来（工具扩展接口） | N1b | 待做 |

### N4 是本阶段的重头（grill 后新增的结论已并入）

- 整理模式 CONSOLIDATING 不只是「压记忆」，更是「反思 + 经验教训 +
  流程优化 + 记忆链接」；**Assigner（上司）是天然的评判者**，JD 里写
  KPI；
- 原始 ReAct 对话记录归 Agent 私有区（PrivateStore），是记忆的**原始
  层**（已拆为独立卡 `raw-transcript-layer`），条目网络是**精炼层**，
  两条检索路径分开；
- 岗人交接**不全量克隆**技能（A 邮件交接 / 当师傅，B 吸收后独立演进）；
- 量力而行：工具返回超过模型剩余处理能力就截断，记预警。

## 最小测试向量（贯穿所有任务的唯一判据）

```text
外部事件进来 → 拆成任务（岗位 + SOP 知识）→ 人类审批（人类任务）
→ 不可逆外部操作（幂等键去重，全程入 Journal）→ 复盘（审计）
```

这条链路**语义闭合之前**，不实现任何场景资产（软件公司/小说工作室/
电商/自媒体/知识星球）。

## 验收门

- v0.11 门：至少一个场景包端到端 demo 运行，内核代码零改动
  （受测试向量纪律约束：语义未闭合前不启动场景资产）。
- 每个 TODO 独立可验收；`uv run pytest -q` 全绿 + ruff/mypy。
- 关键不变量（对应 SPEC §11）：
  - [ ] 任一任务/决策记录其生效的知识与策略版本快照
  - [ ] 新 PackageVersion 发布不改变运行中任务的版本绑定
  - [ ] 外部事件 `(source, external_id)` 幂等去重，不重复投递
  - [ ] 任意审批任务/未决效果都有终止路径或显式 escalation
  - [ ] root 不能扩大自身 authorization，不能绕过 Owner escalation
  - [ ] 未如实申报的可执行条目加载即拒；任一能力安装可审计追溯
  - [ ] 同 Deployment 内私有记忆/凭证/资产引用不交叉泄漏
  - [ ] 任一 effect 可追溯到 Intent、Task、PackageVersion、Principal
  - [ ] 最小测试向量端到端闭合，内核代码零改动
