# v0.12.0 计划 — 真实 LLM API 接入验证

**Date:** 2026-08-24
**Status:** 计划中（v0.11 门通过后启动）

## 版本定位

系统至今运行在 `fake_llm` 之上（确定性、零成本）；v0.12 把
`llm_gateway`/`llm_dispatcher` 接到**真实 LLM 供应商**，端到端验证
"async 续延 + 工具调用 + 失败恢复 + 限额记账"在真实 API 上成立。
这是 v1.0（一人公司可用）的前置：内核与 Agent 引擎的全部推理语义
必须被真实 API 实测过。

```text
v0.12 — 真实 LLM API 接入验证（fake_llm 保留为测试/回放后端）
```

## 范围

- 供应商适配：**OpenAI 兼容协议优先**（DeepSeek / OpenAI / 本地
  vLLM 等），Anthropic 视需要；
- 凭证接入：API 密钥经 CredentialStore（引用式，不进
  Journal/审计/prompt，T12b 已有机制）；
- 配置化：`llm_profile` 映射真实模型名/参数（temperature/max_tokens/
  timeout_ticks 沿用）；
- 失败语义：限流/超时/网络错误 → pending op 重试策略（v0.10
  llm_dispatcher 路径），区分可重试与不可重试；
- 限额记账：验证 Agent 内 LLM 限额（v0.11 预算拆分后的归属）在
  真实调用上正确累计；
- 工具调用链：真实 API 的 function-calling 结果 → ActionPlan →
  Intents 全链路；
- 测试策略：`fake_llm` **保留**为单元/回放后端（确定性）；
  真实 API 验证走集成测试（标记、可跳过），CI 不依赖真实密钥。

## 依赖

- v0.11：N4 记忆与注入（prompt 由注入集构成）、N5 任务治理绑定
  （DecisionClaim 上下文）为真实 API 提供了真实输入形态；
- 不依赖 N6/N7/N8/N9（可并行推进）。

## 验收标准

- [ ] 真实 API 端到端 demo：单 agent 多轮 ReAct（含工具调用）跑通
- [ ] 失败恢复：模拟限流/超时后重试成功，无重复外部效应
- [ ] 限额记账在真实调用上正确（与 fake_llm 路径语义一致）
- [ ] 密钥不进 Journal/审计/prompt（有断言）
- [ ] fake_llm 路径全绿（单元层不回退）；集成测试可跳过
- [ ] `uv run pytest -q` 全绿；ruff/mypy 通过
