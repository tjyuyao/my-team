> 知识，不再有独立流程引擎。本卡是它坍缩后的继承者，只做「把治理
> 接到任务上」这一件事。

## 目标

让任务能**审批**（人类点头）、**升级**（卡住时求救）、**裁决**（意见
冲突时定谁说了算），并记录每个任务当时用了哪个版本的技能/策略。

## 做什么（大白话）

1. **审批 = 一个待办任务**。需要人类点头的事，系统就创建一个「人类
   任务」（`kind = work | approval | decision | consultation`），发邮件
   通知，人类在界面或邮件里回「同意/拒绝」，系统按回复决定下一步。
   **不搞单独的审批门**——审批就是任务的一种，和 AI 任务走同一条路。

2. **升级 = 统一的一种求救**。任务卡住（没人批、超时、出异常）时，
   沿「上司」边往上求救。全系统**只有这一种**升级表示（`on × mode ×
   target`），不重复造轮子。

3. **裁决 = 冲突时谁说了算**。多个岗位对同一件事意见不同时，查「谁
   对这个领域有最终决定权」来定（Authority）。裁决在**验证**阶段出
   结论，**提交**阶段再确认一次。下属的裁决权永远不超过上司（委派
   单调）。

4. **三重检查，互不替代**：
   - **能不能调用**这个工具（能力，OperationPolicy）；
   - **有没有权**做这个决定（裁决，Authority）；
   - **该批的批了吗**（审批任务状态）。
   三者各管各的——「内容已定稿」不等于「不用审批」。

5. **版本戳**：每个任务/决策记录「当时生效的技能/工具/策略版本」，
   之后能查「当时它知道什么」（和 N4 记忆注入的版本戳是一件事的
   两面）。

## 产出

- 人类任务模型 + 审批流程（复用已有的「人类动作经界面/邮件注入」
  这条现成路径）；
- 裁决算法接到验证/提交两阶段；
- 升级统一表示（三处共用同一 schema）；
- 版本戳落地（任务/决策 → 生效版本）。

## 验收标准

- [ ] 审批经「人类任务 + 邮件」完成，没有旁路入口
- [ ] 全系统只有一种升级表示（代码里不存在第二种）
- [ ] 裁决在验证出结论、提交再确认；下属裁决权 ≤ 上司
- [ ] 「内容定稿」不能绕过审批（三重检查互不替代）
- [ ] 任务/决策记录版本戳
- [ ] `uv run pytest -q` 全绿；ruff/mypy 通过
